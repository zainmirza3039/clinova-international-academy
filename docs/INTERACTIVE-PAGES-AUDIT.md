## Local changes in this slice

- Added the certificate-information route and footer link, with source-backed guide links, search, count announcement and explicit public-service limitations.
- Added a format-only certificate-code interaction. Valid syntax always produces an unavailable/not-checked message; it never claims a certificate result.
- Added a collaboration proposal draft checker. It validates only in the browser and never reports a received submission.
- Removed the direct browser-side certificate insert and revoke handlers/controls; the admin certificate panel is read-only and explicitly states issuance is disabled because no authoritative server-side eligibility endpoint exists.
- No Supabase migration or schema change was added. Server-side certificate eligibility enforcement remains absent; actual hosted privileges are unverified.
- Added synthetic admin UI regression coverage: even with completed and active enrolments and both gates open, no certificate issue/revoke action or client write is available. This tests the interface only, not database RLS.
- Lazy-loaded `/admin/*` through the existing `Suspense` boundary alongside `/certification`, `/verify`, and `/training-partners`; the latest local production build has a 491.17 kB entry chunk and a 20.37 kB admin chunk, below Vite's 500 kB advisory threshold.
- Maintained tests cover certificate catalogue links and empty states, malformed/valid-format-but-unverified codes, local collaboration validation/clearing/repeat submit/no persistence, and all 39 exact source-hash inventory rows with version-specific confirmation required.
- At the time of this local implementation snapshot, no SQL migration had been added or applied, and no remote database call, configuration change, production request, branch, commit, push, PR, merge or deployment had been made.

## Browser smoke and remaining blockers

Headless Chrome for Testing 151.0.7922.34 visited `/certification`, `/verify` and `/training-partners` at 1440×900 and simulated 390×844. All six page/viewport combinations returned HTTP 200 with no horizontal overflow. Enter submission and Clear worked on verification; Enter-triggered validation, truthful no-submission status and Clear worked on the collaboration form. All non-local requests were blocked; 14 blocked asset requests produced expected `ERR_FAILED` console messages, and there were no Supabase requests. This is a local smoke check, not physical-device or screen-reader QA.

A follow-up keyboard-only smoke passed across all three pages at both sizes. It confirmed the skip link is first focus and transfers focus to main, keyboard search/no-match recovery, malformed and valid-looking-but-unverified certificate codes, verification Clear, partnership error-summary focus and error-link recovery, local validation, repeated Enter without a changed outcome or false success, and draft Clear. Ten non-local requests were blocked and no Supabase host was requested. This remains automated browser QA; real screen-reader and physical-device checks are pending.

Before any release or live activation, the owner still needs exact-hash clinical/editorial approval for all 39 records; an academy-approved certificate eligibility model and server-enforced issuance/verification endpoint with tests proving unauthorized or incomplete enrolments cannot issue; a schema/permission plan and synthetic-account non-production RLS validation before any future database change; an approved privacy/retention policy and abuse-controlled partnership endpoint; an authenticated collaboration review workflow; and separate approval for any production or deployment action. Keep issuance disabled until those server-side controls exist.
